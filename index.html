PROJECT 03 · SECURITY VALIDATION

문제를 재현하고, 막은 뒤 다시 확인했습니다

04

구축한 공공자전거 서비스에서 접근제어, QR 토큰, 동시 대여 처리, 운영자료 접근과 관련된 문제를 시나리오로 재현했습니다. 대표 사례는 요청이 어디에서 발생하고 어떤 계층에서 대응했는지까지 흐름으로 정리했습니다.

A01 · REPRESENTATIVE CASE

IDOR 접근제어 문제

사용자 식별값을 변경했을 때 다른 사용자의 대여 정보를 조회하거나 강제 반납할 수 있는 문제를 확인했습니다.

01 · REPRODUCE 요청 값 변경

대여 조회·반납 요청의 사용자 식별값을 변경해 타 사용자 데이터 접근 가능 여부를 확인했습니다.

02 · FIX Flask 권한 검증

요청 사용자와 대여 정보의 관계를 확인하도록 서버 측 접근제어 로직을 보완했습니다.

03 · DETECT WAF · Wazuh

관련 비정상 요청과 애플리케이션 이벤트가 탐지되도록 보안 계층을 구성했습니다.

04 · RETEST 동일 요청 재수행

같은 방식으로 다시 요청해 타 사용자 정보 접근이 제한되는지 확인했습니다.

A02

QR Token 변조

예측 가능한 대여 토큰의 변조 가능성을 확인하고, 토큰 검증과 재사용 방지를 적용한 뒤 WAF · Snort · Wazuh에서 관련 이벤트를 확인했습니다.

A03

동일 자전거 동시 대여

동일한 자전거에 여러 대여 요청이 동시에 발생하는 상황을 재현하고, 대여 상태 확인과 처리 과정에서 중복 대여가 발생할 수 있는지 검증했습니다.

A04

운영자료 비인가 접근

인증 없이 접근 가능한 운영자료 경로를 확인하고, 접근 정책을 수정한 뒤 Snort · WAF · pfSense에서 관련 접근을 제한했습니다.

Simmit Pay

Network Design Enterprise Infrastructure Access Control Network Security
07

본사·지사·재택근무 환경을 구성하고, 업무별 접근권한과 안전한 통신 구조를 구현한 금융회사 사내망 프로젝트

Simmit Pay는 가상의 금융회사를 대상으로 본사, 지사, 재택근무자가 함께 사용하는 기업 내부 네트워크 환경을 구성한 프로젝트입니다.

본사는 인사관리·개발·영업·금융재무·인프라보안·서버 영역을 6개의 VLAN으로 분리하고, 지사는 인사관리·영업·서버 영역을 3개의 VLAN으로 분리했습니다.

각 구간이 필요한 서비스에만 접근할 수 있도록 ACL을 적용하고, 본사와 지사는 VPN을 통해 암호화된 통신 경로를 구성했습니다. 외부 통신에는 NAT를 적용했으며, WEB · DB · DNS · LOG · SFTP 서비스가 정해진 정책에 따라 통신하는지 최종 점검했습니다.

SERVICE WEB · DB · DNS · LOG · SFTP
